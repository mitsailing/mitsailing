# CASL Prisma App Authorization Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `@casl/prisma` the explicit boundary for row-scoped app authorization while keeping simple feature gates as CASL ability checks.

**Architecture:** CASL remains the app authorization engine; `@casl/prisma` is used only where an ability must become a Prisma `WhereInput`. Add a small local CASL Prisma wrapper so generated Prisma client typing, `accessibleBy`, and future CASL API changes are isolated in one file. Extract repeated public event-registration ownership filters into one helper so registration create, cancel, and query paths cannot drift.

**Tech Stack:** TypeScript, Next.js App Router, Better Auth, CASL, `@casl/prisma`, Prisma 7 generated client, Vitest.

---

## Background Decisions

- CASL does not own roles. It owns ability rules. This repo may use one role or many roles as input, then compile those roles into one ability.
- Better Auth stores multiple roles as a comma-separated `user.role` string. This repo already parses that through `parseRoles()` before building CASL rules.
- Do not replace simple permission checks like `ability.can(Permission.ADMIN_VIEW, AuthSubject.PERMISSION)` with Prisma queries.
- Do use `@casl/prisma` for record-scoped filters such as event admin access and viewer event-registration ownership.
- Do not add CASL's Prisma Client extension in this plan. The installed `@casl/prisma@1.6.2` package in this repo does not export `createCaslExtension`, so this plan keeps explicit `ForbiddenError` handling.

## File Structure

- Create `src/libs/auth/caslPrisma.ts`: one local wrapper for `@casl/prisma` exports and generated Prisma `TypeMap` typing.
- Modify `src/libs/auth/permissions.ts`: import CASL Prisma types/factory from the wrapper instead of directly from `@casl/prisma`.
- Create `src/libs/mit-sailing/eventRegistrationAuthorization.ts`: one helper that returns the Prisma `WhereInput` for the current viewer's own event registrations.
- Create `src/libs/mit-sailing/eventRegistrationAuthorization.test.ts`: focused unit test for the helper.
- Modify `src/libs/mit-sailing/eventRegistrationActions.ts`: replace repeated inline ability/filter creation with the helper.
- Modify `src/libs/mit-sailing/eventQueries.ts`: replace repeated inline ability/filter creation with the helper.
- Modify `src/libs/admin/events/eventAdminAuthorization.ts`: import `accessibleBy` from the local wrapper.
- Modify tests only where import behavior or expectations need to be adjusted.

## Concrete Before/After Example

Current code repeats the same CASL Prisma rule setup in multiple public event-registration paths:

```ts
const registrationAccessWhere = accessibleBy(
  createAuthAbility({
    grants: [],
    role: Role.USER,
    userId: user.id,
  }),
  AuthAction.UPDATE
).EventRegistration;
```

After this refactor, the public registration action, cancel action, and event detail query all call one helper:

```ts
const registrationAccessWhere = getViewerEventRegistrationAccessWhere(user.id);
```

Concrete operational benefit: if MIT Sailing later allows a parent, team captain, or staff proxy to manage another sailor's public registration, the ownership rule changes in one helper and one CASL rule instead of being reimplemented in three Prisma queries. The SQL filter remains generated by `@casl/prisma`, so a missed manual `userId` condition is less likely.

Create `src/libs/auth/caslPrisma.ts`:

```ts
import {
  accessibleBy,
  createPrismaAbilityFor,
  ParsingQueryError,
  prismaQuery,
} from '@casl/prisma';
import type {
  Model,
  PrismaModel,
  PrismaQueryOf,
  Subjects,
  WhereInputOf,
} from '@casl/prisma';
import type { Prisma } from '@/generated/prisma/client';

export {
  accessibleBy,
  ParsingQueryError,
  prismaQuery,
};

export type {
  Model,
  PrismaModel,
  Subjects,
};

export const createPrismaAuthAbility =
  createPrismaAbilityFor<Prisma.TypeMap>();

export type AppPrismaQuery<
  TModel extends PrismaModel = PrismaModel,
> = PrismaQueryOf<Prisma.TypeMap, TModel>;

export type AppWhereInput<TModelName extends Prisma.ModelName> = WhereInputOf<
  Prisma.TypeMap,
  TModelName
>;
```

```ts
import 'server-only';
import type { Prisma } from '@/generated/prisma/client';
import { accessibleBy } from '@/libs/auth/caslPrisma';
import { AuthAction, createAuthAbility } from '@/libs/auth/permissions';
import { Role } from '@/libs/auth/roles';

export function getViewerEventRegistrationAccessWhere(
  userId: string
): Prisma.EventRegistrationWhereInput {
  return accessibleBy(
    createAuthAbility({
      grants: [],
      role: Role.USER,
      userId,
    }),
    AuthAction.UPDATE
  ).EventRegistration;
}
```
